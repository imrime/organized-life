## 3. Boot sequence (`js/main.js`)

1. Import `version.js`, `i18n.js`; language = `settings.language` if stored, else `en` (Russian is chosen explicitly by the user).
2. Render a minimal splash (room colour + app name) — no blank screen.
3. `db.open()` → if blocked/unsupported show a fatal error card with "Export is impossible: storage unavailable" and a retry button.
4. Load all collections into `store` (parallel `getAll`).
5. Read `meta.schemaVersion`; if lower than `SCHEMA_VERSION` → snapshot raw data into `meta.preMigrationBackup` → run migrations → write back in one transaction.
6. If first launch (no `profile/settings`) → `seed.js` creates profile singletons, finance categories, default account, products, exercises, routines, base clothing.
7. Resolve initial route: hash route if present, else `settings.lastLocationId` (if not hidden), else `bedroom`.
8. Render `<App/>`; start reminder engine; `sw-register.js`.
   - If the location's tour is not in `settings.toursSeen` (and onboarding is done) → start the room tour.
   - If `profile/sleepPlan.pendingBedAt` is set and the current time is past wake time → show the "Good morning" sleep-log prompt (F-8).
9. If `VERSION` differs from `settings.lastSeenVersion` → toast "Updated to vX.Y.Z" and store the new value.
10. After onboarding completes → `navigator.storage.persist()`.

Startup target: interactive in < 1.5 s on a mid-range Android phone with warm cache ([§10](#10-performance-budgets)).

## 4. Feature module contract

Each folder under `js/features/<name>/` contains:

| File | Responsibility | May import |
|------|----------------|------------|
| `model.js` | Pure logic: defaults, validation, derived values (e.g. next alarm, streaks, stock level). No DOM, no store. **Unit-tested.** | `core/time.js`, `core/money.js`, `core/units.js`, `core/text.js` |
| `actions.js` | Mutations via `store.mutate()`; cross-feature effects are orchestrated here (e.g. checkout writes transactions + inventory). | `model.js`, `core/store.js`, other features' `actions.js` |
| `selectors.js` | Read-models for windows, badges, next-task strip, reminders (pure functions of store state). | `model.js` |
| `window.js` | Preact components for the feature's sheet(s) and pages. Lazily imported. | `ui/*`, `selectors.js`, `actions.js` |
| `reminders.js` (optional) | `collectReminders(state, range)` → reminder instances for the engine. | `model.js` |
| `badge.js` (optional) | `badge(state, objectId)` → `{text, tone}` or `null`; and `visualState(state)` for the scene. | `selectors.js` |

Rules:
- `model.js` and `selectors.js` never touch IndexedDB or the DOM → testable in Node.
- A feature never writes another feature's collection directly from `window.js`; it calls that feature's `actions.js`.
- Strings only through `t('feature.key')`.

## 5. State store and persistence

### 5.1 IndexedDB layout (`js/core/db.js`, `js/core/schema.js`)
- Database name: `organized-life`. `DB_VERSION` = structural version (bumped only when stores/indexes change). `SCHEMA_VERSION` = data shape version (bumped with each data migration).
- One object store per collection, `keyPath: 'id'`, no secondary indexes (queries run in memory).
- Store `profile` holds singletons with fixed ids (`settings`, `character`, `sleepPlan`, `fitness`).
- Store `meta` holds `{id: 'schema', version}`, `{id: 'install', installId, firstLaunchAt}`, `{id: 'preMigrationBackup', data}`, `{id: 'undo', …}` (not persisted across sessions — in memory only).
- Collections are listed in [04-data-model.md](04-data-model.md).

### 5.2 Store API (`js/core/store.js`)

```js
// Read
store.get(collection, id)                       // → record | undefined (ignores soft-deleted)
store.all(collection, { includeDeleted = false }) // → readonly array (cached, stable identity until changed)
store.profile(id)                               // → singleton record

// Write — atomic, write-through, undoable
const token = await store.mutate(labelKey, (tx) => {
  tx.insert(collection, partialRecord)          // fills id, createdAt, updatedAt; returns record
  tx.patch(collection, id, partial)             // shallow merge, bumps updatedAt
  tx.replace(collection, record)
  tx.remove(collection, id)                     // soft delete: sets deletedAt
  tx.setProfile(id, partial)
})
store.undo(token)                               // restores before-images of the whole mutation

// Subscribe
store.subscribe(listener)                       // called after every committed mutation with changed collection names
useCollection(collection, selector?)            // Preact hook, re-renders on change of that collection
useProfile(id)
```

Semantics:
1. `mutate` applies changes to in-memory copies, then opens **one** IndexedDB `readwrite` transaction over all touched stores.
2. On commit → swap in the new state, notify subscribers, emit `bus 'saved'` (drives the autosave indicator and object feedback animation).
3. On failure → discard in-memory changes, emit `'save-failed'` → toast "Couldn't save. Your last change was not kept." (with *Retry* when the error is transient). Quota errors show a storage-full dialog with *Export backup*.
4. Before-images are kept for the last 20 mutations (in memory) to support *Undo*.
5. Records are deep-frozen in development (`BUILD === 'dev'`) to catch accidental mutation.

### 5.3 Purge
Soft-deleted records older than 30 days are hard-deleted at startup (one transaction).

## 8. Routing

Hash-based (works on GitHub Pages without server rewrites):

| Route | Meaning |
|-------|---------|
| `#/` | Restore last location |
| `#/<locationId>` | Show location, no sheet |
| `#/<locationId>/<objectSlug>` | Location + object's window (`#/kitchen/refrigerator`) |
| `#/<locationId>/<objectSlug>/<page>/<id?>` | Deep page (`#/bedroom/desk-notebook/task/9f…`) — P2 |
| `#/<locationId>/~<system>` | System window: `~map`, `~list`, `~me`, `~settings`, `~quick` |

History rules (Android back button and iOS swipe-back behave like an app):
- Opening a sheet → `pushState`. Back closes the sheet (dirty guard applies).
- Pushing a sheet page → `pushState`. Back pops the page.
- Changing location → `replaceState` (Back from a bare location leaves the app, like a native root screen).
- Hidden location (Study/Gym hidden in Settings) in a route → redirect to the bedroom with a toast "Study is hidden — show it in Settings → Places".

## 9. Reminder engine (architecture)

`js/core/reminders.js`; rules per source are in [05 §3](05-cross-system.md#3-reminder-engine).

- Each feature exports `collectReminders(state, {from, to})` returning instances `{key, source, objectId, window, title, at, kind: 'alarm'|'reminder'|'digest', severity}`. `key` is stable: `<source>:<recordId>:<YYYY-MM-DD>T<HH:MM>`.
- Engine loop (only while the page is visible): compute instances for `[now − 12 h, now + 24 h]`, schedule a single `setTimeout` to the next due instance (capped at 60 s, re-armed after any mutation or `visibilitychange`).
- When due: if `reminderState[key]` has no `firedAt` → fire (banner / alarm overlay / system notification if permitted and page hidden) → persist `firedAt`.
- On start/visibility: instances due in the past 12 h without `firedAt` and not acknowledged → "missed" list (next-task strip + *Missed* section of the relevant window).
- Snooze writes `snoozedUntil`; dismiss writes `ackAt`.
- **Nightstand power mode** (`core/power.js`): the engine stops its regular loop and keeps exactly **one** `setTimeout` armed to the next alarm instance (or snooze end); non-alarm reminders are deferred to wake time (quiet hours). The clock display is driven by a separate timeout aligned to the next minute boundary. Leaving Nightstand mode restores the normal loop and recomputes everything.
- Timers are never trusted for exactness after the device throttles them: every wake-up re-reads `Date.now()` and fires all instances whose time has passed (a late alarm still rings, with its original time shown).

## 10. Performance budgets

| Metric | Budget |
|--------|--------|
| Critical JS (main, core, ui shell, scene, current room art) | ≤ 140 KB uncompressed |
| Each feature window module | ≤ 40 KB uncompressed, lazy-loaded (but precached by the SW) |
| CSS total | ≤ 40 KB |
| Final room background (WebP) | ≤ 250 KB each; object sprites ≤ 30 KB each |
| Sounds | ≤ 400 KB total (AAC `.m4a` for iOS + fallback) |
| Startup (warm cache, mid-range Android) | interactive < 1.5 s |
| Location transition | ≤ 300 ms, 60 fps (transform/opacity only) |
| Sheet open | first frame < 100 ms after tap (skeleton while the window module loads) |
| Store size tested | 20 000 records without visible lag (< 50 ms for any selector) |
| Nightstand mode | Scene, character and sheets unmounted; zero running CSS animations and `requestAnimationFrame` loops; ≤ 2 JS wake-ups per minute (clock tick + alarm timer); no network or storage writes except when the alarm rings; black (`#000`) background so OLED pixels are off. Verified with the browser performance panel (idle main thread) and an overnight on-charger test ([03 §5.4](03-ux-shell.md#54-alarm-overlay-and-nightstand-mode)) |

## 11. Browser support, security, error handling

- **Supported:** iOS/iPadOS Safari 16.4+ (home-screen PWA and browser), Android Chrome 110+, latest desktop Chrome/Edge/Firefox/Safari (development and large screens). Features used: ES modules, dynamic `import()`, IndexedDB, container queries, `dvh`, `crypto.randomUUID`, `Intl`, Screen Wake Lock (optional, feature-detected), Vibration (optional), Notifications (optional).
- **CSP** (meta tag in `index.html`):
  `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; media-src 'self'; connect-src 'self'; font-src 'self'; object-src 'none'; base-uri 'self'; form-action 'none'; manifest-src 'self'; worker-src 'self'`
  (`'unsafe-inline'` for styles only — Preact sets inline `style` for scene positioning.)
- **External links** entered by the user: only `http:`/`https:` accepted; rendered with `target="_blank" rel="noopener noreferrer"`.
- **Global error boundary:** a window that throws shows "Something went wrong in this window" with *Close* and *Copy details*; the scene stays usable. Errors are logged to the console only (no telemetry).

## 12. Testing

- **Unit tests (MVP, every feature):** `tests/unit/<feature>.test.js` cover `model.js` and `selectors.js`: validation, defaults, recurrence expansion, next alarm, streaks, stock levels, recipe matching, checkout math, budget totals, reminder collection, next-task ranking, migrations.
- **Harness:** `tests/harness.js` exports `describe/it/expect` (toBe, toEqual, toThrow, toBeCloseTo). `tests/index.html` imports all test files and prints results; `tests/run-node.mjs` does the same in Node (CI).
- **Store tests** run only in the browser runner (real IndexedDB, database name `organized-life-test`, deleted after the run).
- **Manual QA:** checklist in [07 §5](07-roadmap.md#5-manual-qa-checklist-per-release), executed on iPhone (home-screen PWA) and Android (installed PWA) before each MINOR release.
- **Later:** Playwright e2e for the vertical slice and checkout flow.
